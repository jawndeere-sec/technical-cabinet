# Verifying AI Output Against Evidence

- A polished answer is a candidate result. Before using it, compare it with the task, the source, and the standard the work must meet.

## Two independent checks

**Accuracy** asks whether the claims present are supported. **Completeness** asks whether the answer left out a requirement or fact that changes the decision. An answer can pass one and fail the other. Specific figures, quotations, citations, and dates deserve particular attention: detail can look authoritative without having a source. Also check for contradictions across a long answer and whether the question's framing pushed the model toward the answer I wanted to hear.

## Make the result inspectable

State that missing evidence should remain missing, and request source locations for claims that matter. Then open the cited material and verify the claim yourself; a citation supplied by the model is a lead, not independent proof. Choose review depth by consequence: exploratory drafting needs less scrutiny than a client-facing, regulated, legal, or financially material deliverable. For numerical work, executing code makes a calculation reproducible, but the generated code and its inputs still need review.

## Reuse boundary

Set the review gate before the answer arrives, not after a confident-sounding draft tempts me to skip it. If a task needs professional judgment or a claim cannot be traced to evidence, more prompting is not a substitute for an accountable reviewer. This is a **course-derived evaluation framework**, not a measured Claude evaluation or a claim that a certification was completed.
